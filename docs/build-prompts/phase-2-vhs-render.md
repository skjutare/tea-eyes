# Phase 2 — VHS Image Rendering

**Goal:** Claude can see *pixels*, not just ASCII. Add a `tui_render_image` MCP tool that uses Charm's VHS to produce PNG/GIF output of a TUI session, returned as an MCP image content block so Claude sees it natively.

**Estimated effort:** 1–2 days

**Prerequisites:** Phase 1 complete. VHS installed locally for development
(`brew install vhs` on macOS, or use Charm's install script).

---

## Prompt to give Claude Code

> Implement Phase 2 of tea-eyes per `docs/plan.md`. Add image rendering via
> Charm's VHS, exposed as a new MCP tool `tui_render_image`. This is what makes
> tea-eyes "Playwright-equivalent" — Claude can now judge color, spacing,
> alignment, and typography by looking at actual pixels.
>
> ## Dependencies
>
> No new Go dependencies (VHS is invoked as a subprocess). Document the
> external dependencies in README:
> - `vhs` (required) — `brew install vhs` or
>   `go install github.com/charmbracelet/vhs@latest`
> - `ttyd` (required by vhs) — `brew install ttyd`
> - `ffmpeg` (required by vhs) — `brew install ffmpeg`
>
> Add a `tea-eyes doctor` subcommand to `cmd/tea-eyes/main.go` that checks for
> these binaries on PATH and reports their versions, or prints install hints if
> missing.
>
> ## Implementation
>
> ### 1. `internal/render/vhs.go`
>
> Generate a `.tape` file from an interaction spec, run `vhs`, return image
> bytes.
>
> ```go
> type RenderOpts struct {
>     Command    string
>     Args       []string
>     Keys       []string        // same notation as keys package
>     Width      int             // columns, default 80
>     Height     int             // rows, default 24
>     FontFamily string          // default "JetBrains Mono"
>     FontSize   int             // default 14
>     Theme      string          // default "Dracula"; see `vhs themes`
>     Format     string          // "png" or "gif"
>     FrameAtMs  int             // for png: which frame to keep (default: last)
>     Padding    int             // pixels around the terminal, default 20
>     SettleMs   int             // ms between key sends, default 300
> }
>
> type Render struct {
>     Bytes      []byte
>     Mime       string  // "image/png" or "image/gif"
>     Width      int     // pixel dimensions
>     Height     int
>     TapeSource string  // for debugging / cache key
> }
>
> func NewRenderer(workDir string) *Renderer
> func (r *Renderer) Render(ctx context.Context, opts RenderOpts) (Render, error)
> ```
>
> ### 2. Tape file generation
>
> Build a `.tape` file from `RenderOpts`. Reference the VHS docs
> (https://github.com/charmbracelet/vhs) for syntax. A typical generated tape:
>
> ```
> # Generated by tea-eyes — do not edit manually
> Output frame.png
> Set Shell "bash"
> Set FontFamily "JetBrains Mono"
> Set FontSize 14
> Set Width 80
> Set Height 24
> Set Theme "Dracula"
> Set Padding 20
> Hide
> Type "exec ./hello-tui"
> Enter
> Show
> Sleep 300ms
> Type " "
> Sleep 300ms
> Screenshot frame.png
> ```
>
> Map the keys notation from `internal/keys/` to VHS commands:
> - Plain runes / strings → `Type "..."`
> - `enter`, `escape`, `tab`, `backspace`, `space`, arrows, page keys → matching
>   VHS commands (`Enter`, `Escape`, `Tab`, etc.)
> - `ctrl+X`, `alt+X` → `Ctrl+X`, `Alt+X`
> - Numeric repeat: not exposed in v1; just emit one VHS command per key.
>
> For PNG output use VHS's `Screenshot` command at the right point. For GIF use
> `Output frame.gif` and let it record the whole session.
>
> ### 3. Caching
>
> Compute a SHA-256 over the canonicalized RenderOpts (sorted JSON) and use
> that as the cache key.
>
> Cache directory: `$XDG_CACHE_HOME/tea-eyes/renders/` (or
> `~/.cache/tea-eyes/renders/` fallback). Each entry: `<hash>.png` plus
> `<hash>.tape` next to it for debugging.
>
> Add `--no-cache` to the MCP tool inputs (default false). Add a `tea-eyes
> cache clean` subcommand.
>
> Cache is opportunistic: if the file exists and is non-empty, reuse it. No
> staleness check — users can `tea-eyes cache clean` if they change fonts or
> themes outside the tool inputs.
>
> ### 4. Server integration
>
> Register a new MCP tool:
>
> **Tool: `tui_render_image`**
>
> Inputs (extends `tui_capture_text` with rendering options):
>
> | name | type | required | default | description |
> |------|------|----------|---------|-------------|
> | `command` | string | yes | — | binary or shell command to run |
> | `args` | []string | no | `[]` | arguments |
> | `keys` | []string | no | `[]` | key sequence |
> | `width` | int | no | 80 | columns |
> | `height` | int | no | 24 | rows |
> | `font_family` | string | no | "JetBrains Mono" | monospace font name |
> | `font_size` | int | no | 14 | font size |
> | `theme` | string | no | "Dracula" | VHS theme name |
> | `format` | enum | no | "png" | "png" or "gif" |
> | `padding` | int | no | 20 | px padding |
> | `settle_ms` | int | no | 300 | ms between keys |
> | `no_cache` | bool | no | false | bypass cache |
> | `cwd` | string | no | "" | working directory |
>
> Output: the tool returns an MCP **image content block** (base64-encoded image
> with mime type), plus a small text content block with metadata:
>
> ```json
> {
>   "format": "png",
>   "width": 800,
>   "height": 480,
>   "cache_hit": true,
>   "cache_path": "~/.cache/tea-eyes/renders/abc123.png"
> }
> ```
>
> Important: in `mcp-go`, the way to return an image is to construct an image
> content block in the tool result. Verify the exact API in mcp-go's docs and
> tests; do not guess.
>
> ### 5. `examples/multi-pane/`
>
> A second Bubble Tea example that exercises layout primitives — two panels
> side-by-side with a thin border, focus highlighting, a status bar at the
> bottom. Press tab to switch focus, q to quit. ~150 lines. Use this as the
> demo target for image rendering tests.
>
> ### 6. `test/integration/render_test.go`
>
> End-to-end test:
> 1. Skip the test if `vhs` is not on PATH (use `t.Skip` with an informative
>    message).
> 2. Build `examples/multi-pane`.
> 3. Call `tui_render_image` via the MCP server.
> 4. Assert the returned PNG is non-empty, decodes successfully, and has
>    dimensions roughly matching expected (W × font width + padding × 2,
>    H × font height + padding × 2; allow ±50 px slack).
> 5. Call again with the same inputs; assert `cache_hit: true`.
> 6. Call with `no_cache: true`; assert it re-renders.
>
> Mark this test with a build tag `//go:build integration` so it can be
> opted out in CI environments without VHS. Add a `make test-integration`
> target.
